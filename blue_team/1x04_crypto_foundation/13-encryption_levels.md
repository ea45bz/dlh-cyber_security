# 1 Comparison table of the 6 encryption levels from Sec+ 1.4:

| Level     | Scope                | Performance                   | Key Management        | Use Case                              |
| --------- | -------------------- | ----------------------------- | --------------------- | ------------------------------------- |
| Full-disk | Entire disk          | High at boot/I/O              | One host key          | Lost/stolen laptops                   |
| Partition | One partition        | Similar to full-disk          | One key per partition | Separate sensitive OS/data partitions |
| Volume    | Logical volume       | Low with hardware support     | One key per volume    | LVM / SAN storage                     |
| File      | Individual files     | Only protected files affected | Per-user/file keys    | Selected documents/images             |
| Database  | Entire DB/tablespace | Moderate query overhead       | DBMS/HSM-managed key  | Transparent protection for DB apps    |
| Record    | Row/field level      | Highest overhead              | Per-field/app key     | Least-privilege sensitive fields      |

# 2 MedDefense Encryption‑Level Map

| Data Store                                                                                                                | Recommended Level  | Why this is best for MedDefense                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Patient records – PostgreSQL (ehr-db-01)**                                                                              | Database/Record    | The entire database contains PHI that must be readable by clinical staff, so a transparent layer keeps performance acceptable while protecting all tables; sensitive columns can be encrypted if query patterns permit. Each record is tampered to restrict manipulation |
| **Backup data – NAS‑01**                                                                                                  | Volume             | The NAS stores large backups from many sources; encrypting at the volume level protects everything on that shared folder, is easy to manage across multiple disks, and imposes only a small I/O overhead (~5 %).                                                         |
| **Financial records – MySQL (billing‑srv-01)**                                                                            | Database/Partition | The database holds billing data that must be searchable; TDE protects the whole tablespace while column‑level encryption safeguards the most regulated values.                                                                                                           |
| Compliance demands “data‑at‑rest” protection but allows system software to stay clear – e.g., PCI‑DSS for cardholder data |
| Card‑holder data lives in an encrypted partition                                                                          |
| **Medical images – PACS (pacs-srv-01)**                                                                                   | File               | Images are large files; encrypting at the file level allows selective protection of only those folders that contain PHI and keeps read/write overhead low compared to full‑disk encryption.                                                                              |
| **Email data – O365**                                                                                                     | File               | encrypting per‑mailbox file, allows selectove protection and keeps read/write overhead                                                                                                                                                                                   |
| **Employee laptops**                                                                                                      | Full‑disk          | The laptop contains OS, application data, and PHI on the workstation—full‑disk encryption protects all content if the device is lost or stolen.                                                                                                                          |
| **BD Alaris pump firmware / configuration**                                                                               | File/Record        | Firmware is a small binary that should be cryptographically protected from tampering; encrypting the image and storing its key in a hardware security module prevents unauthorized updates.                                                                              |
