## Provide examples of common CWEs and their potential impact on software security.

| CWE                                                                                              | Typical Scenario                                              | Why It Matters (Impact)                                                                                           |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **CWE‑79: Improper Neutralization of Input During Web Page Generation (XSS)**                    | User input rendered without escaping.                         | Enables attackers to inject malicious scripts that run in a victim’s browser, stealing cookies or session tokens. |
| **CWE‑89: Improper Neutralization of Special Elements used in an SQL Statement (SQL Injection)** | Concatenated user data into SQL queries.                      | Gives attackers read/write access to databases, data exfiltration, or privilege escalation.                       |
| **CWE‑119: Improper Restriction of Operations within the Bounds of a Buffer (Buffer Overflow)**  | Unsanitized `strcpy`/`memcpy`.                                | Allows execution of arbitrary code on the host system—remote code execution or kernel exploits.                   |
| **CWE‑326: Inadequate Encryption Strength**                                                      | Using weak hashing algorithms (e.g., MD5) to store passwords. | Enables password cracking and credential compromise.                                                              |
| **CWE‑285: Improper Authorization**                                                              | Role checks performed only on the client side.                | Lets unauthorized users perform privileged actions (admin UI, API endpoints).                                     |
| **CWE‑200: Information Exposure**                                                                | Debug logs containing sensitive data sent to production logs. | Leaks personal or corporate secrets to attackers who can read logs.                                               |
| **CWE‑787: Out-of-bounds Write**                                                                 | Writing past the end of an array.                             | Similar to buffer overflows; can corrupt memory, crash applications, or allow code execution.                     |
| **CWE‑601: URL Redirection and Frame Injection (Open Redirect)**                                 | Unvalidated redirects to user-supplied URLs.                  | Phishing attacks, session fixation, or redirecting users to malicious sites.                                      |
| **CWE‑284: Improper Access Control**                                                             | API endpoint does not check authentication tokens.            | Anyone can access protected data or operations.                                                                   |

## How would you prioritize addressing these weaknesses in a software development project?

| Priority Tier              | Criteria                                                                                                                                                                      | Typical CWEs to Target                                                                                                       | Why It Gets the Attention                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Tier 1 – Must‑Fix**      | • High CVSS base score (≥ 9.0). <br>• Enables remote code execution, privilege escalation, or data exfiltration.<br>• No authentication or minimal user interaction required. | CWE‑119 (Buffer Overflow), CWE‑89 (SQL Injection), CWE‑79 (XSS when stored in a database), CWE‑284 (Improper Access Control) | Attackers can act immediately; business impact is catastrophic.                |
| **Tier 2 – High Priority** | • Medium–high CVSS (7–8.9). <br>• Compromise of sensitive data or critical components.<br>• Requires some attacker skill or credentials.                                      | CWE‑326 (Weak Encryption), CWE‑200 (Information Exposure), CWE‑601 (Open Redirect)                                           | Significant risk but often needs an additional step; still worth fixing early. |
| **Tier 3 – Moderate**      | • Low–medium CVSS (4–6.9). <br>• Impact limited to a subset of users or data, or requires user interaction.                                                                   | CWE‑285 (Improper Authorization), CWE‑787 (Out-of-bounds Write), CWE‑784 (Information Exposure via File)                     | Worth addressing before launch but can be scheduled with routine releases.     |
| **Tier 4 – Low**           | • Minor CVSS (< 4). <br>• Rarely exploited or limited to legacy features.                                                                                                     | CWE‑749 (Improper Restriction of Operations within the Bounds of a Stack Frame), CWE‑1130 (Excessive Path Length)            | Nice to fix, but can remain in backlog until later maintenance cycles.         |

### Practical Checklist for Development Teams

| Step                | Action                                                                                          |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| **Onboarding**      | Include a quick “CWE cheat sheet” in your dev handbook.                                         |
| **Code Review**     | Verify that reviewers reference the CWE ID when raising issues.                                 |
| **CI Pipeline**     | Run a static analyzer that tags code with CWEs; fail builds if Tier 1 or 2 CWEs appear.         |
| **Release Cadence** | Tag every release with “CWE‑fixed” list; include in changelog for auditability.                 |
| **Security Audits** | At each audit, verify that all known high‑severity CWEs have been fixed in the current version. |
